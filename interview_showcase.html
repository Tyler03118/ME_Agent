System Architecture

The core is a single LangGraph workflow with bounded conditional control flow. It behaves like an agent where it matters, while avoiding unnecessary multi-agent complexity for a small technical corpus.

validate_inputReject empty or invalid questions.
route_queryMap ECU models and intent to required sources.
retrieve_contextUse keyword, vector, or hybrid retrieval.
broaden_retrieveOne bounded retry when retrieval confidence is low.
generate_answerDeepSeek generation with extractive fallback.
verify_answerCheck answer overlap with retrieved evidence.
compute_confidenceBlend retrieval, coverage, and verifier support.
human_reviewFlag unsupported or low-confidence outputs.
RAG

Source-constrained retrieval

Comparison and feature-availability questions force coverage across the relevant ECU manuals, reducing one-sided answers.

Agent

Bounded control flow

Conditional edges handle out-of-scope questions, broadened retrieval, and human review without creating an uncontrolled loop.

MLOps

MLflow packaging

The assistant is logged as a pyfunc model with signature, input example, pip requirements, and corpus artifacts.

Design Decisions & Trade-offs

Trade-off

Deterministic router, not LLM router

The corpus has explicit model IDs and source boundaries. Rules are lower-cost, lower-latency, easier to test, and less likely to misroute exact specification questions. An LLM router becomes useful when the taxonomy grows or becomes ambiguous.

Trade-off

Keyword-first hybrid retrieval

Specs depend on exact tokens like model numbers, units, and command strings. Keyword retrieval protects precision; vector retrieval improves recall for phrasing variation. Results are merged and deduplicated without reranking.

Trade-off

Heuristic confidence

Confidence blends retrieval relevance, source coverage, and verifier support. It is not a calibrated probability; it is an operational triage signal for human review.

Likely Interview Questions

Why rule-based routing instead of an LLM router?
Because this corpus has explicit ECU model IDs, families, and comparison keywords. Deterministic routing gives lower latency, zero model cost, full unit-testability, and predictable source coverage. I would add an LLM router only when the corpus grows beyond explicit taxonomy or starts receiving ambiguous natural-language intents.
How do you prevent hallucination?
I constrain the model with retrieved context, include source citations, verify answer/context overlap after generation, compute confidence from retrieval and verifier signals, and route unsupported or low-confidence answers to human review. The system also says when context is insufficient instead of forcing an answer.
Why hybrid retrieval?
ECU questions often hinge on exact strings: model names, temperatures, storage sizes, command flags, and units. Keyword retrieval is strong there. Vector retrieval helps when the user asks semantically, such as "harshest environment" rather than "operating temperature." Hybrid keeps the exact-match precision and adds semantic recall.
How would this scale to thousands of manuals?
I would move from in-memory indexing to a persistent vector database, add incremental ingestion keyed by document version, use Markdown-aware section and table chunking, add a reranker, cache common queries, and track retrieval drift through MLflow evaluation artifacts and sampled SME review.
What makes this an agent rather than a fixed pipeline?
It is intentionally not an open-ended autonomous agent. It is a bounded agentic workflow: it validates input, routes dynamically, conditionally broadens retrieval, verifies outputs, computes confidence, and decides whether to finalize or escalate. That is the right level of agency for a safety-sensitive engineering assistant.
How do you know the evaluation is honest?
The challenge CSV scores against Expected_Answer using semantic similarity and token coverage. The custom stress CSV adds explicit Required_Facts, Forbidden_Facts, Expected_Sources, and Expected_Route fields for production-style regression checks. The offline fallback score reflects a generic extractive path, while live DeepSeek runs provide the primary quality signal.

Known Limits & Next Steps

Limit

Character-window chunking

Current chunking is deterministic and simple, but can split Markdown tables. Next step: Markdown-aware section/table chunking that keeps headings and rows together.

Limit

No reranker yet

Hybrid retrieval currently merges keyword-first and vector results. A cross-encoder or LLM reranker would improve precision at larger corpus scale.

Limit

Confidence is heuristic

The score is a triage signal, not a calibrated probability. Production use should calibrate it against SME-labeled samples.

Closing line: "I would rather defend a simple, testable system with known limits than ship a complex agent whose behavior is hard to explain. This project is designed to be reviewable first, then extendable."
