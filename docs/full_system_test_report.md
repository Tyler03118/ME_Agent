## Architecture Summary

Pipeline nodes in the LangGraph workflow:

1. `validate_input`
2. `route_query`
3. `retrieve_context`
4. `generate_answer`
5. `verify_answer`
6. `compute_confidence`
7. `maybe_human_review`

Generation behavior:

- If `DEEPSEEK_API_KEY` is available and `langchain-openai` is installed, `generate_answer` calls DeepSeek through OpenAI-compatible `ChatOpenAI` using `deepseek-v4-flash` and `https://api.deepseek.com`.
- The client uses `ME_AGENT_MODEL_TIMEOUT_SECONDS=8` and `ME_AGENT_MODEL_MAX_RETRIES=0` by default so provider timeouts fall back inside the 10-second target instead of multiplying latency through retries.
- If the provider call fails or times out, the node falls back to deterministic grounded extraction.
- Live model answers are post-processed by a grounded stabilizer that normalizes model formatting and ensures critical retrieved manual facts remain explicit.

Retrieval behavior:

- Manuals are split into metadata-preserving chunks in `chunking.py` before retrieval.
- `ME_AGENT_RETRIEVER_MODE` supports `keyword`, `vector`, and `hybrid`.
- `keyword` uses deterministic token-overlap retrieval for exact specs and commands and does not initialize embeddings.
- `vector` uses `EmbeddingModel` plus a local in-memory `VectorStore` built once at startup.
- `hybrid` is the default and only merges keyword-first results with vector recall while preserving required source coverage for comparison and feature-availability queries.

## Remaining Risks

- Live DeepSeek availability is network/provider dependent; timeout fallback is intentional and now measured.
- The vector retriever uses local sparse embeddings rather than a hosted neural embedding model backed by FAISS or Chroma.
- Deterministic fallback and answer stabilization are tuned to the provided ECU challenge corpus and fixed eval set.
- MLflow logging still uses CloudPickle object serialization and emits a warning; acceptable for smoke validation but not ideal for production packaging.
- Databricks Asset Bundle packaging is present; actual workspace deployment still depends on workspace credentials, cluster policy, and secret configuration.
- Evaluation scoring uses key-fact matching, not semantic grading; useful for this challenge set but not a general evaluator.
