# Evaluation Strategy

The evaluation set is a CSV of golden ECU questions with expected answers. The
evaluator runs the full assistant graph for each question, records the produced
answer, and scores it with provider-independent signals instead of
question-id-specific facts.

## Automated Metrics

- `accuracy`: percentage of cases whose combined score meets
  `ME_AGENT_EVAL_PASS_THRESHOLD`.
- `semantic_similarity`: cosine similarity between the expected answer and the
  produced answer using the configured embedding layer.
- `token_coverage`: normalized overlap of important expected-answer tokens in
  the produced answer.
- `used_llm_rate`: share of answers generated by the configured DeepSeek model.
- `fallback_cases`: count of answers produced by the extractive fallback path.
- `avg_latency_seconds` and `max_latency_seconds`: end-to-end query latency.
- `source_diagnostic` and `route_diagnostic`: retrieved source count and route
  category for debugging retrieval coverage.

The default pass score is:

```text
0.65 * semantic_similarity + 0.35 * token_coverage >= ME_AGENT_EVAL_PASS_THRESHOLD
```

The metric is intentionally heuristic. It is useful for regression testing and
challenge reproducibility, but it is not a substitute for factual review.

## Validation Modes

- Live evaluation: uses DeepSeek when `ME_AGENT_API_KEY` is configured and should
  report `used_llm_rate=1.0`.
- Offline evaluation: forces a missing key and validates retrieval plus extractive
  fallback behavior without network access.
- Retrieval-mode smoke tests: run representative questions with `keyword`,
  `vector`, and `hybrid` modes to verify that all retriever paths execute.

## Human Review Strategy

Production validation should sample answers with low confidence, unsupported
verifier status, comparison questions, and configuration commands. The current
agent flags low-confidence answers for human review instead of silently treating
all answers as equally reliable.
