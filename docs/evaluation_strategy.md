# Evaluation Strategy

The evaluation system supports both the provided golden ECU questions and a
custom stress set. Each row runs the full assistant graph, records the produced
answer, and scores it with provider-independent signals.

The base schema is compatible with the challenge CSV. Stress rows may also use
optional columns: `Required_Facts`, `Forbidden_Facts`, `Expected_Sources`, and
`Expected_Route`. Pipe-separated values in those columns drive deterministic
fact recall, forbidden-claim, source, and route checks.

## Automated Metrics

- `accuracy`: percentage of cases whose combined score meets
  `ME_AGENT_EVAL_PASS_THRESHOLD`.
- `semantic_similarity`: cosine similarity between the expected answer and the
  produced answer using the configured embedding layer.
- `token_coverage`: normalized overlap of important expected-answer tokens in
  the produced answer.
- `used_llm_rate`: share of answers generated by the configured DeepSeek model.
- `fallback_cases`: count of answers produced by the extractive fallback path.
- `avg_latency_seconds` and `max_latency_seconds`: end-to-end query latency.
- `required_fact_recall`: share of configured or inferred technical facts present
  in the answer.
- `forbidden_fact_violations`: explicit forbidden claims found in the answer,
  excluding values mentioned only in a local rejection/contradiction context.
- `source_match`: recall of expected source files in the response sources.
- `route_match`: whether the observed route matches `Expected_Route`.
- `source_diagnostic` and `route_diagnostic`: retrieved source count and route
  category for debugging retrieval coverage.

The challenge CSV uses this score. `required_fact_recall` is inferred from the
expected answer when the CSV does not provide explicit `Required_Facts`:

```text
0.45 * semantic_similarity
+ 0.20 * token_coverage
+ 0.35 * required_fact_recall
>= ME_AGENT_EVAL_PASS_THRESHOLD
```

Rows with enhanced criteria use:

```text
0.35 * semantic_similarity
+ 0.20 * token_coverage
+ 0.25 * required_fact_recall
+ 0.10 * source_match
+ 0.10 * route_match
- forbidden_fact_penalty
>= ME_AGENT_EVAL_PASS_THRESHOLD
```

The metric is intentionally heuristic and deterministic. It is useful for
regression testing and challenge reproducibility, but it is not a substitute for
SME factual review or a future LLM-judge layer.

## Validation Modes

- Live evaluation: uses DeepSeek when the configured API-key environment variable
  (default `DEEPSEEK_API_KEY`) is configured and should report `used_llm_rate=1.0`.
- Offline evaluation: forces a missing key and validates retrieval plus extractive
  fallback behavior without network access.
- Stress evaluation: set `ME_AGENT_EVAL_PATH=data/eval/stress-questions.csv`
  to run paraphrase, negative-evidence, prompt-injection, out-of-scope,
  multi-hop, exact-command, and terse-comparison cases.
- Retrieval-mode smoke tests: run representative questions with `keyword`,
  `vector`, and `hybrid` modes to verify that all retriever paths execute.

## Continuous Validation Loop

The regression loop has three layers:

1. Golden dataset: run `python scripts/run_eval.py` on the CSV questions and log
   accuracy, latency, `used_llm_rate`, fallback counts, similarity, and token
   coverage to MLflow.
2. Artifact review: inspect `eval_results.json` or render it as a visual HTML
   report for representative question, expected answer, agent answer, sources,
   confidence, and route diagnostics.
3. SME sampling: manually review low-confidence answers, comparison questions,
   configuration commands, and any failed or borderline cases before treating a
   metric improvement as real quality improvement.

## Visual Reports

The JSON artifact can be rendered into a self-contained HTML report with summary
cards, score bars, per-category pass rates, failed-case and human-review sections,
and expandable case-level evidence. The renderer has no frontend build step and
can optionally embed a Markdown appendix when one is provided.

```bash
python scripts/run_eval.py \
  --eval-path data/eval/stress-questions.csv \
  --output reports/stress_eval_results.json \
  --html-report reports/stress_eval_report.html

python scripts/render_eval_report.py \
  eval_results.json \
  reports/eval_report.html
```

`mlflow.evaluate` is not required for this small structured task because the
project computes task-specific metrics directly and logs them with
`mlflow.log_metric` plus the detailed JSON artifact. If the dataset grows, the
logged artifact can be converted into an MLflow evaluation table for richer model
comparison.

## Human Review Strategy

Production validation should sample answers with low confidence, unsupported
verifier status, comparison questions, and configuration commands. The current
agent flags low-confidence answers for human review instead of silently treating
all answers as equally reliable.
